# Tower Quest — すれ違い回数で挑むタワー

## 1. 目的

端末同士ですれ違った事実を、そのままタワーへの出撃機会に変換する。単なる累計値ではなく、1 回のすれ違いにつき 1 人の勇者を 1 回だけ出撃させる。

既存作品の名称・画像・音源・文章は使わず、「会った人が助けに来る」「1 人ずつ行動する」「敵を倒した勇者は次の階へ進む」という体験を Project Encounter の世界観で実装する。

## 2. 出撃権

- `encounter_logs` の 1 行を出撃権 1 回とする。
- 同じ相手と 2 回すれ違った場合も、別のログ 2 行として 2 回出撃できる。
- 使ったログは `tower_dispatches.encounter_log_id` に記録し、二重消費しない。
- 出撃権はタワーへの入場回数ではなく、勇者 1 人を出撃させる回数。
- 敵を倒した勇者が次の階へ進むときは、追加の出撃権を消費しない。
- 敵を倒せず帰還した後に次の勇者を出す場合は、新しい出撃権を 1 回消費する。
- ブラウザ開発時は、同じデータ形状を localStorage のテストログで再現する。

## 3. 戦闘状態

`entering -> command -> attacking | casting -> enemy-defeated -> floor-transition -> command` または `tired-return -> ready`

- `entering`: 画面外から戦闘位置まで歩く。出撃開始時に一度だけ再生。
- `command`: 「戦う」「魔法」を受け付ける待機状態。
- `attacking` / `casting`: その場で行動する。`entering` へ戻してはならない。
- `tired-return`: 敵を倒せなかった勇者が、肩を落としてゆっくり帰る。走らない。
- `enemy-defeated`: 勇者は戦闘位置に残って勝利し、帰還させない。
- `floor-transition`: 同じ勇者のまま次階へ移り、敵を入れ替えた後 `command` に戻す。

ボタンは `command` の間だけ有効にし、連打による多重ダメージと状態の巻き戻りを防ぐ。

## 4. ハンマー

- 柄は右手の掌を通り、頭部は身体の前方・右上に見える位置に置く。
- 待機時に背中側へ突き抜けて見える角度は禁止。
- 攻撃時は右手を支点に前方へ振り下ろす。
- 魔法時はハンマーを身体の前で掲げ、攻撃の歩行モーションは再生しない。

## 5. 受入基準

- [x] 同じ相手のすれ違いログが 2 行あれば、2 回分の未使用出撃権になる。
- [x] 一度消費したログは再起動後も再利用できない。
- [x] 「戦う」「魔法」を押しても入場歩行が再生されない。
- [x] 敵が残った場合、勇者は走らず疲れた歩き方で帰る。
- [x] 敵を倒した場合、勇者は帰らず同じ位置から次の階を戦える。
- [x] ハンマーの柄が手を通り、頭部が背中側に見えない。
- [x] 行動中のボタン連打で HP や出撃権が二重に変化しない。
