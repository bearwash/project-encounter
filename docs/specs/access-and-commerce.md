# Access & Commerce — ゲスト開始、ログイン制限、コイン購入

## 1. ゲスト開始

- 初回起動ではログイン画面を強制表示しない。
- タイトル、本編の導入、ストア商品の閲覧、法務・サポートページはゲストで利用できる。
- 起動時に匿名 Supabase ユーザーを自動作成しない。

## 2. ログインが必要な機能

- タワーへの入場・出撃
- 工房でのアバター編集、色変更、名前・一言の保存
- コイン購入の確定
- アカウント削除

未ログインで対象操作を選ぶと、元の画面を失わないモーダルを表示する。ログイン後は要求していた画面へ戻れる。

## 3. ログイン方式

- 本番: Apple、Google、メールのマジックリンクを Supabase Auth へ接続する。
- 開発: `NODE_ENV !== production` または `NEXT_PUBLIC_ENABLE_TEST_LOGIN=1` のときだけ端末内テストログインを表示する。
- Supabase 未設定の本番ビルドでは偽の成功状態を作らず、設定不足を明示する。
- 旧 anonymous session はログイン済みとして扱わない。

## 4. コイン

- コイン残高はユーザー単位で扱う。
- 開発・審査検証ビルドでは「テスト購入」を 0 円で実行し、実クレジット決済を発生させない。
- テスト残高は端末内台帳へ記録し、本番残高と混ぜない。
- 本番の購入導線は商品 ID、購入開始、復元、レシート検証の境界を先に定義する。
- 購入検証APIは明示ログインの access token で認証し、クライアント指定の user ID や付与量を信用しない。
- ネイティブ StoreKit / Play Billing とサーバー検証が未接続なら、本番購入ボタンは「ストア接続待ち」として無効化する。

## 5. 商品 ID

| 商品 | Product ID | 付与コイン |
|---|---|---:|
| ひとつかみ | `com.projectencounter.coins.120` | 120 |
| ポーチ | `com.projectencounter.coins.650` | 650 |
| トランク | `com.projectencounter.coins.1400` | 1,400 |

価格表示は StoreKit / Play Billing から返されたローカライズ済み文字列を使い、ソースに本番価格を固定しない。

## 6. 受入基準

- [x] 初回起動時にログイン操作なしでタイトルを開始できる。
- [x] ゲストがタワーまたは工房を選ぶとログイン案内が出る。
- [x] 開発モードのテスト購入は 0 円で、実決済 API を呼ばない。
- [x] 本番未接続状態で購入成功を装わない。
- [x] 購入・復元・レシート検証の接続点と商品 ID が一箇所に集約されている。
- [x] 工房で設定した名前と一言が、広場で近づいた相手の表示形式と同じ形で確認できる。

## 7. 公開プロフィールの安全

- 名前・一言を公開する前にコミュニティルールと利用規約へ明示同意する。
- URL、連絡先、明確な暴言・性的表現等をクライアントとサーバーの両方で拒否する。
- 広場の住人カードに、混同しない独立した「通報」「ブロック」を表示する。
- ブロックした相手は挨拶、広場、タワーから即時除外する。
- 通報は対象 ID、表示内容のスナップショット、理由だけを送る。すれ違い時刻・場所は送らない。
- 運営者は `store/community-operations.md` の期限で通報を確認・対応する。
