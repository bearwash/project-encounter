# Encounter Plaza — ホーム画面（広場ビュー）

> 関連: [要件定義 §3.2 B, §3.3](../要件定義.md) / [encounter-popup.md](encounter-popup.md) / [avatar.md](avatar.md) / [walk-mode.md](walk-mode.md)

## 1. ゴール (What & Why)
これまですれ違ったアバターたちが、**横スクロールの「街並み」** を思い思いに歩き回る、アプリの "住所" となるホーム画面。
リスト的に過去を振り返るのではなく、**「いつ開いても、知らない誰かたちが今日も広場にいる」生活感** を提供することがゴール。

設計の参照点は **Wii の Mii パレード／Mii チャンネル** の "賑わい"。住人としてのアバターは消えず、新しい人がワラワラ追加されていく。

## 2. ユーザーストーリー
- ユーザーとして、すれ違った人たちが集まっている広場を眺めたい。
- ユーザーとして、気になるアバターをタップして詳細（名前・最終すれ違い・累計回数・メッセージ）を見たい。
- ユーザーとして、住人が増えるほど画面が賑やかになる感覚を味わいたい。
- ユーザーとして、画面外にもまだ住人がいることが分かりつつ、スクロールで全員にアクセスできてほしい。

## 3. スコープ
### In Scope
- 横スクロール 2D の街並みビュー
- アバターの自律行動（左右移動、立ち止まり、振り向き）
- 同時表示 **最大 30 人**、超過分は **画面外（左右）に存在し、スクロールで見える**
- アバタータップで詳細パネル（名前 / 最終すれ違い日時 / 累計回数 / 一言メッセージ）
- 空状態（住人 0 人）の誘導 UI
- ウォークモードへの導線（[walk-mode.md](walk-mode.md)）
- ポップアップからの合流アニメ受け入れ（[encounter-popup.md](encounter-popup.md) §4.7）

### Out of Scope
- アバター同士の相互作用（会話・反応）→ Phase 2 以降
- 検索・フィルタ機能
- ブロック・通報（要件次第で別途）
- 俯瞰ビュー / 等角ビュー（Phase 2 以降の検討）

## 4. 仕様詳細

### 4.0 表示対象の絞り込み
広場に表示するのは **`users_cache` に存在する（= [profile-sync.md](profile-sync.md) で fetch 完了した）住人のみ**。
プロフィール未取得の `user_id` は `encounter_logs` に残っていても **広場には一切現れない**。「半端な状態を見せない」ポリシー（[profile-sync.md](profile-sync.md) §5.5）。

```sql
-- 広場の住人ソース
SELECT u.user_id, u.display_name, u.avatar_code, u.message,
       u.first_seen_at, u.last_seen_at, u.encounter_count
FROM users_cache u
ORDER BY u.last_seen_at DESC;
```

### 4.1 カメラ・レイアウト
- **横スクロール 2D**。カメラは横視点（地面に並んで歩いているのを横から見る）。
- 縦方向のサイズは 1 画面固定（スクロールは横のみ）。
- ステージ幅は **画面幅 × `ceil(住人数 / 30)`**（30 人ごとに 1 画面分の広さを動的に拡張）。

### 4.1.1 背景テーマ：夕方の公園（固定）
- **舞台**: 公園。中立的でノスタルジックな雰囲気を担保し、住人の「思い思いに過ごす」挙動と矛盾しない。
- **時間帯**: 薄明るい夕方（マジックアワー）で **固定**。
  - 空: オレンジ〜紫のグラデーション
  - 街灯がポツポツ灯り始める
  - 影が長く伸び、フラットベクターでも空間に奥行きが出る
  - MVP では時間連動は行わず、Phase 2 以降で検討
- **3 層パララックス**:
  - **遠景**: 夕焼け空のグラデーション + 遠くの木立シルエット
  - **中景**: 地面（芝生 + 散歩道）
  - **前景**: 街灯、ベンチ、桜の木 1〜2 本
- **配置オブジェクト**:
  - 街灯（複数。夕方の灯りで賑わいを演出。CSS で柔らかい光のアニメ）
  - ベンチ（複数。Phase 2 で住人が座る挙動の実装余地）
  - 桜の木 1〜2 本（季節感 + ピンクの色アクセント）
  - 自販機・遊具・噴水・池は **採用しない**

### 4.2 住人の配置と密度
- **同時表示 30 人** を「現在のビューポート + 前後余白」に配置。
- 住人合計が 30 人以下なら、ステージ全体に均等分布。
- 31 人以上のときは、各画面に 25〜35 人収まるよう **動的に位置を再計算**（クラスタリング）。
- 重なりは許容するが、**z-index は y 座標（足元位置）昇順** で奥行き感を出す。

### 4.3 自律行動（アイドリング）
詳細は [avatar.md](avatar.md) §5。
- 各住人は以下の状態を確率的に遷移する有限状態機械:
  - `walking`（左右にトコトコ移動、3〜8 秒）
  - `standing`（立ち止まって周りを見る、2〜5 秒）
  - `looking`（左右にきょろきょろ、1〜3 秒）
- 状態遷移は **個体ごとに独立した乱数シード**（`user_id` をシードに）→ アプリ再起動しても挙動の "個性" がぶれない。
- 端（ステージの左右端）に到達したら自動で反転。

### 4.4 ポップアップからの合流アニメ（ゲート通過）
- ポップアップシーン（[encounter-popup.md](encounter-popup.md) §5.7）の最後で、ユーザーと挨拶した全員 + ユーザーがゲートをくぐる動作に入り、カメラがパンしながら広場ビューへクロスフェードする。
- 広場到着時の挙動:
  1. **画面の左端（ゲートの内側）から、合流したアバターたちが順次フレームインしてくる**。等間隔（200ms 程度）で次々に出てくる「行列が広場に流れ込む」表現。
  2. 出てきたアバターはそれぞれランダムな目的地へ歩いて散らばり、各自のアイドリング状態（`walking` / `standing` / `looking`）に入る。
  3. ユーザーのアバターはゲートの内側で立ち止まり、画面遷移後はカメラ操作の主体に戻る（ユーザー自身は広場ビューでは "観察者視点" になり、自アバターは表示しない選択も検討 — オープン課題）。
- 「NEW」バッジは表示しない（入口でハイタッチした記憶が鮮明なので不要）。代わりに、合流直後の数秒は新住人が画面左端付近に固まって見えるため、視認性は十分確保される。

### 4.5 タップ詳細パネル
住人タップで、画面下からスライドアップするボトムシート（高さ 40vh）を表示。
- アバター（拡大版）
- `display_name`
- 「最終すれ違い: {相対表記}」（例: 「3 分前」「昨日」「1 週間前」）
- 「累計 N 回すれ違い」
- `message`（一言）
- パネルの外をタップ or 下スワイプで閉じる

### 4.6 空状態（住人 0 人）
- 中央に大きめのテキスト「歩き出すと、ここに住人が増えていきます」
- 下に **「ウォークモードを始める」** ボタン → [walk-mode.md](walk-mode.md) へ遷移
- 背景はステージの遠景＋中景のみ表示（中央にぼんやり街灯がひとつ灯っている等）

### 4.7 リアルタイム更新
- ポップアップ画面から戻ってきたとき、**広場の住人リストは最新の `users_cache` と同期** されている必要がある。
- ただし合流アニメはポップアップ側で完了させるため、戻ってきた時点では既に住人として存在する。

### 4.8 パフォーマンス指針
- 同時アニメーション要素は最大 30 体 + 背景 3 層 = 33 要素。
- アバター 1 体あたりの DOM ノード数は **30 個以下**（[avatar.md](avatar.md) §3）。
- すべて CSS `@keyframes` で動かし、JS タイマーは状態遷移（数秒〜数十秒間隔）のみ。
- スクロールは `overflow-x: auto` + `transform` ベースで GPU 合成を効かせる。
- 中位 Android 端末（2 世代前）で **30fps 以上** を維持することを最低基準とする。

## 5. 受入基準
- [ ] 住人 0 人のとき、空状態 UI とウォークモード導線が表示される
- [ ] 住人 1 人のとき、その人物が画面中央付近で歩き回っている
- [ ] 住人 30 人のとき、画面内に概ね 30 人が分布し、横スクロールしてもステージ端で止まる
- [ ] 住人 60 人のとき、横スクロールで「裏」の 30 人にアクセスできる
- [ ] アバタータップで詳細パネルが開き、外タップで閉じる
- [ ] ポップアップから戻ったとき、表示したアバター全員が画面左端から順次フレームインして合流している
- [ ] 30 人 + 背景 3 層の同時描画で、中位端末で 30fps を下回らない
- [ ] 同じ `user_id` のアバターは、再起動後も同じ行動パターン傾向（移動の癖）を見せる
- [ ] アプリをバックグラウンドにしても、フォアグラウンド復帰時に住人配置が壊れていない

### 4.9 住人の卒業・間引きルール
- **一切行わない**。すれ違った住人は何ヶ月経っても広場に残り続ける。
- 設計判断: 「コレクション体験を絶対に損なわない」を最優先とする。住人数が増えるほどステージが横に伸びる挙動は仕様として受容する。
- 数百人〜千人規模に達したときの UX（スクロール体験、検索導線、日付ジャンプ等）は Phase 2 で別途検討するが、**MVP 段階では考慮不要**。

## 7. オープン課題
- [ ] 詳細パネルからの「広場の中で再度ポップアップ風に挨拶を見る」機能の要否
- [ ] 30 人クラスタリングの具体アルゴリズム（時系列順 / ランダム / 累計回数順）
- [ ] 日時の相対表記ルール（i18n 含む）
- [ ] BGM / 環境音の有無（ノスタルジック・ポップ路線との整合）
- [ ] 広場ビューでユーザー自身のアバターを表示するか（現状は観察者視点として非表示の想定）
