# Walk Mode — iOS ウォークモード（省電力待機画面）

> 関連: [要件定義 §3.2 D, §4.1](../要件定義.md) / [ble-handshake.md](ble-handshake.md)

## 1. ゴール (What & Why)
iOS のバックグラウンド BLE 制約を回避し、確実なすれ違い成立を実現するための「あえてフォアグラウンドで待機する」専用画面。
3DS 時代の「電源を入れたまま持ち歩く」体験の再現でもある。

## 2. ユーザーストーリー
- ユーザーとして、長時間散歩するときに「確実にすれ違いを検出してほしい」モードを使いたい。
- ユーザーとして、ポケット内での誤タップで終了したり、画面が明るくバッテリーを食ったりしないでほしい。

## 3. スコープ
### In Scope
- 専用のフルスクリーン待機画面
- 画面の暗転（黒一色 + 最小限の状態表示）
- 終了操作の意図確認（ロック機能）
- BLE スキャン・アドバタイズの高頻度モード
- スクリーン常時オン設定

### Out of Scope
- 完全な画面 OFF（iOS では実現不能。バックグラウンド遷移してしまう）
- 加速度センサーによる自動歩行検出（後フェーズ検討）

## 4. 仕様詳細

### 4.1 起動導線
- ホーム画面（[encounter-list.md](encounter-list.md)）から「ウォークモード開始」ボタン
- 起動時にユーザーに以下を案内:
  - 画面を暗くしたままにする
  - 画面ロックは OFF にする必要がある（iOS の Auto-Lock 設定）
  - バッテリー消費は通常より大きい

### 4.2 画面構成
- 背景: 純黒 `#000000`
- 中央: 小さな脈動アイコン（呼吸する点。アプリが生きている証拠）
- 下部: 経過時間、検出回数（任意）
- 右上: 終了ボタン（ロック解除を経由）

### 4.3 ロック機能
誤タップ防止のため、終了操作は 2 段階:
1. 終了ボタンを長押し（2 秒）
2. 「終了しますか?」確認ダイアログで「はい」

### 4.4 BLE 動作
- スキャン: 連続実行 or 短間隔（実装で最適化）
- アドバタイズ: 高頻度
- 通常モードよりバッテリー消費が大きいことを許容

### 4.5 スクリーン制御
- `keep-awake` 相当のフラグを ON にし、自動ロックを抑止
- 終了時に必ず OFF に戻す（バッテリーリーク防止）

### 4.6 異常系
- BLE がオフになった → 中央アイコンを警告色に変更し、復帰を待つ
- アプリがバックグラウンドに送られた → 通常モードに自動降格（ウォークモードは強制終了）
- 画面ロックが入った → 同上

## 5. 受入基準
- [ ] ウォークモード起動中、画面が自動で消えない
- [ ] 終了ボタンを通常タップしても終了しない（長押し → ダイアログが必要）
- [ ] ウォークモード中はすれ違い検出頻度が通常時より明確に高い
- [ ] バックグラウンドに送られたら適切に通常モードへ戻る
- [ ] 終了後、画面の常時オン設定が確実に解除される
