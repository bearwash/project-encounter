# Encounter Popup — 起動時の連続ポップアップ

> 関連: [要件定義 §3.1, §3.2 A](../要件定義.md) / [ble-handshake.md](ble-handshake.md) / [encounter-list.md](encounter-list.md)

## 1. ゴール (What & Why)
バックグラウンドでサイレントに蓄積されたすれ違いデータを、アプリを開いた瞬間に「サプライズ」として一気に開示する。
OS プッシュ通知では再現できない「あの頃のすれ違い体験」を演出する、プロダクトの中核 UX。

## 2. ユーザーストーリー
- ユーザーとして、しばらくぶりにアプリを開いたとき、その間にすれ違った全員を順番に見たい。
- ユーザーとして、興味がない相手はサッと飛ばしたい。

## 3. スコープ
### In Scope
- アプリ起動時、`encounter_logs.is_read = false` のレコードを順次表示
- 全画面オーバーレイ、「ENCOUNTER!」ネオン演出
- 「次へ」操作による連続入場（前のアバターが消える → 次が入場）
- 既読化（表示済みレコードを `is_read = true` に）
- 0 件のときは表示しない

### Out of Scope
- プッシュ通知（OS 通知）
- ポップアップからのチャット・フォロー等の関係性アクション（後フェーズ）
- アバターの 3D アニメーション（[要件定義 §7 Phase 2](../要件定義.md)）

## 4. 仕様詳細

### 4.1 表示トリガー
アプリがフォアグラウンドになった直後（cold start / warm resume 両方）に、未読件数を判定。

```
on_foreground():
  unread = db.count(encounter_logs where is_read = false)
  if unread > 0:
    navigate_to(EncounterPopupScreen)
```

### 4.2 表示順序
`encountered_at` 昇順（古い順）で表示。ユーザーが「時系列に追体験」する感覚を再現する。

### 4.3 1 画面あたりの表示要素
- 中央: 相手のアバター（[profile.md](profile.md) の `avatar_code` をレンダリング）
- 上部: 「ENCOUNTER!」ネオンタイトル
- アバター下: `display_name`
- 下部: `message`（一言メッセージ）
- 右下: 「次へ」ボタン（最後の 1 件では「閉じる」）

### 4.4 アニメーション仕様
- 入場: 下から or 横からスライドイン（200〜400ms）
- 退場: 「次へ」押下で fade-out + scale-down（150ms）
- 入退場の overlap は 50ms 程度（演出の連続感）
- パフォーマンス: 60fps を維持。低スペック端末では duration を短縮しても良い

### 4.5 既読化のタイミング
**表示が完了した瞬間**（入場アニメ完了時）に `is_read = true` に更新する。
「次へ」を押さずにアプリを閉じても、見た分は既読扱い。

### 4.6 エッジケース
- 表示中に新規エンカウントが発生 → 現在のキューには追加しない（次回起動時に表示）
- DB エラーで `is_read` 更新失敗 → エラーを UI に出さず、次回再表示される（冪等性で許容）
- 未読が大量（100 件超）→ 上限 N 件を表示し、残りはリストに直接送る（N は要検討）

## 5. 受入基準
- [ ] 未読 1 件のとき、起動後に 1 度だけポップアップが出る
- [ ] 未読 3 件のとき、「次へ」を 2 回押すと 3 件目に到達し、3 回目で閉じる
- [ ] 「次へ」連打で順序が破綻しない（前のアバターと次のアバターが重ならない）
- [ ] ポップアップを閉じた直後に再起動しても、同じレコードは再表示されない
- [ ] 未読 0 件のときはポップアップが一切表示されない
- [ ] 60fps を著しく下回らない（中位スペック実機での実測）
